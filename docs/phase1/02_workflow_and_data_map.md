# Phase 1 — Workflow and Data/Artifact Map

Traced from source; "Run" marks what was also exercised on the disposable stack. See `01_baseline_report.md` for the runs and `03_defect_register.md` for the defect IDs.

## 1. Workflows

| Workflow | Entry → path | Reads / writes | Notes |
|---|---|---|---|
| Health / readiness | `GET /health` (static), `GET /health/detailed` (`app/main.py`). Lifespan fails fast if `DATABASE_URL` is missing, the DB is unreachable, or `models/{regressor,classifier,scaler}.pkl` / `feature_importances.json` is missing. | reads `features`, `students` | Run: 200. A short/unset `ADMIN_KEY` only logs a warning (D-04). |
| Student / profile | `app/routers/students.py`: `POST /students`, `GET /students[/{id}]`, `PATCH /students/{id}`, `/status`, `/history` | `students`, `features`, `predictions`, `prediction_history` | Run: create 201, duplicate 409, invalid cgpa 422. Email and branch are immutable via PATCH. No auth (D-12). |
| GitHub ingestion | Pipeline step 2, or `POST /ingest/github[/real]/{id}`. Real: `ingest/github_api.fetch_github_data` (≤ 10 recent repos, total commits per repo, `commit_date = pushed_at`). Synthetic: `ingest/github.py` profiles for ids 1–8. | writes `github_activity` with `ON CONFLICT (student_id, repo_name, commit_date) DO NOTHING` | **Fails on a fresh DB** (D-02). Real call is skipped for 24 h after `github_last_synced` unless `force_refresh`. Silent fallback to synthetic on API error (D-03). |
| LeetCode / coding ingestion | Pipeline step 1, or `POST /ingest/coding[/real]/{id}`. Real: `ingest/leetcode_api.fetch_leetcode_data` (one GraphQL call for aggregate solved counts, then one row per solved problem with invented dates). Synthetic: `ingest/coding.py` (unseeded `random`). | writes `coding_activity` (unique `(student_id, problem_id)`); real path deletes the student's existing rows first | Not run against the real API. `/ingest/coding/real/{id}` invents 30 rows for unknown ids (D-03, D-15). |
| Feature computation | Pipeline step 3 → `features.compute.run_feature_sql_for_student` (`feature_engineering_single.sql`); batch/boot/retrain/`/predict` → `run_feature_sql` (`feature_engineering.sql`). The two SQL files differ by the `student_id` filters and three unused columns in the full version (diffed with comments stripped). | writes `features`; `features.compute` `__main__` also loads, MinMax-scales, writes `models/scaler.pkl`, `features/features_raw.csv`, `features/features_scaled.csv` | Run. Features: `total_problems`, `avg_difficulty`, `consistency_score` (distinct ISO weeks in last 90 days / 13), `commit_frequency` (sum commits / days since earliest `commit_date`), `cgpa` joined from `students`. Seed data yields consistency 0 for all (dates in 2024). |
| ML training / artifacts | `python -m ml.train` (`entrypoint.sh`) and `/admin/retrain`. `load_data` reads `features/features_scaled.csv`, `ml.labels.generate_labels` computes the label (weighted features + N(0,5) noise, seed 42), RandomForest regressor + classifier, 75/25 split, 3-fold CV, dummy baselines. | writes `models/regressor.pkl`, `classifier.pkl`, `feature_importances.json` | Run: trains on 8 rows (D-06). Retrain trains into `models/staging/`, smoke-tests, then renames into `models/`; it first overwrites `models/scaler.pkl` in place (before validation). |
| Prediction + history | `ml.predict.predict` ← pipeline step 4, `POST /predict/{id}`, `python -m ml.predict`. Scales with the saved scaler, clips to [0,1], regressor → score, classifier → category. | upserts `predictions`; inserts `prediction_history` at most once per hour | Run. Models are loaded at import (D-05). Category can disagree with the score thresholds (D-11). |
| Insight generation | `insights/engine.InsightEngine.format_insight` ← pipeline step 5, `GET /insights/{id}`. Raw-value thresholds in `insights/rules.py`, ranked by regressor importance from `feature_importances.json`, plus composite patterns, company tier, 7-day score delta. | reads `features`, `predictions`, `prediction_history` | Run: 200. The router caches the engine and reloads when the importance file's mtime changes. |
| Single-user pipeline | `POST /pipeline/{id}[?force_refresh=true]` → `services/pipeline.run`: coding → GitHub → features → predict → insights. Router returns 404 for an unknown id, 429 within 5 minutes of the last feature computation unless forced. | all of the above | Run. Ingestion errors are recorded per step and do not abort; feature/predict/insight errors raise (D-10). |
| Batch pipeline | `POST /pipeline/batch` (≤ 20 ids, 3 worker threads) calls `run` per id; failures become in-band error items. Does not apply the cooldown (`run` has no cooldown). | all of the above | Run with `[2,3,99]`. |
| Admin retrain | `POST /admin/retrain` (202, background thread, in-process lock + status dict), `GET /admin/retrain/status`. Header `X-Admin-Key` compared to `ADMIN_KEY`. | recomputes features, rewrites scaler, models, importances and CSVs | Run: completed in a few seconds; bypassable with an empty header when `ADMIN_KEY` is unset (D-04); API keeps old models in memory (D-05). Status is lost on restart; no artifact version or rollback record. |
| Dashboard | `dashboard/app.py` → `dashboard/api_client.py` (`requests`, `API_URL`) | none directly | Run: serves 200 and the container can reach the API; page flows not exercised. |

## 3. Reproducibility of the committed models

- Not reproduced. `ml.train` is deterministic given its input CSV (`random_state=42`, fixed noise seed), but the committed CSV (9 rows) cannot be regenerated from the seed (8 rows) without running the random generators, and a boot on the seed produced different importances and different scores (e.g. student 1: 59.8 after boot vs the committed models' output not measured).
- The metrics printed by `ml.train` (R² 0.899, accuracy 0.50) come from a 2-row test split and say nothing about placement outcomes; they must not be reported as validated.
